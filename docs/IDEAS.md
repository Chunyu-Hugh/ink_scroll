## 三、想清楚但不做（附原因）

| 想法 | 为什么不做 |
|---|---|
| WebXR / 头显 | 单文件里维护会话生命周期，收益 < 成本；现场没人戴（见 VISION-3D §6） |
| 自己写投影校准 | MadMapper / TD 做得更好；我们只出参照网格（已实现 `?wall=1`） |
| 3D 全面替换 2D | 2D 是 99% 观众的第一入口；3D 只能是新的一张"卷" |
| 引入 three.js | 171 KB gzip + GLTFLoader 110 KB，破"≤4 CDN/单文件"；自写投影器已够用 |
| 单目深度模型 | transformers.js 748 KB + 19–27 MB 权重，首屏不可接受 |

## 四、待验证的假设（要用真机/真人）

1. **吹气的阈值 0.14** —— 只在我这台机器的假麦克风上校准过，真手机要重调
2. **点云 4000 点是甜点** —— 没在低端安卓上测过帧率
3. **红蓝立体** 在真投影上是否可看 —— 需要用红蓝眼镜实测
4. **展厅光照** 下纸本风格的可读性 —— 强光环境可能过曝

那就优先 1（墨迹记忆）、7（落花到 3D）、12（展厅轮播）。
